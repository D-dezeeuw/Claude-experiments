Gaussian Fluids: WebGL 2 Implementation Plan

Interactive fluid simulation based on "Gaussian Fluids: A Grid-Free Fluid Solver based on Gaussian Spatial Representation" (Xing et al., SIGGRAPH 2025), adapted for real-time rendering with WebGL 2 + GLSL ES 3.0 shaders.

1. Paper Summary & Core Math

1.1 Core Idea

The velocity field u(x) of a fluid is represented as a weighted sum of N anisotropic Gaussian basis functions — directly inspired by 3D Gaussian Splatting, but encoding vector fields instead of radiance. The continuous, differentiable representation is evolved over time by recasting the Navier-Stokes equations as an optimization problem.

1.2 Gaussian Basis Function

Each Gaussian kernel:

G_i(x) = exp( -0.5 · (x - μ_i)^T · Σ_i^{-1} · (x - μ_i) )

Where:

  • μ_i ∈ ℝ^d — center position of the i-th Gaussian
  • Σ_i = R_i · S_i · S_i^T · R_i^T — covariance matrix
  • R_i — rotation matrix (angle θ in 2D, quaternion in 3D)
  • S_i — diagonal scale matrix (stored as log(s) to keep positive)

1.3 Velocity Field

u(x) = Σ_{i=1}^{N} w_i · G_i(x)

Where w_i ∈ ℝ^d is the vector-valued weight (velocity contribution) of the i-th Gaussian.

1.4 Spatial Derivatives (Analytical)

Because each Gaussian is infinitely differentiable, all spatial derivatives are computed analytically:

∇G_i(x) = -Σ_i^{-1} · (x - μ_i) · G_i(x)

The velocity gradient tensor:

∂u_j/∂x_k = Σ_i w_{i,j} · [-Σ_i^{-1} · (x - μ_i)]_k · G_i(x)

2D Vorticity (scalar): ω = ∂u_y/∂x - ∂u_x/∂y

2D Divergence (scalar): ∇·u = ∂u_x/∂x + ∂u_y/∂y

3D Vorticity (vector): ω = ∇ × u

1.5 Navier-Stokes (Incompressible)

∂u/∂t + (u · ∇)u = -(1/ρ)∇p + ν∇²u + f
∇ · u = 0

1.6 Operator-Splitting Solver (Per Time Step)

  1. Reseed — Split Gaussians with high anisotropy ratio (max(s)/min(s) ≥ r_aniso)
  2. Advect — Move Gaussian centers via RK4; covector-advect weights via flow Jacobian
  3. Project — Fix positions/rotations, optimize weights + scales to minimize physics losses

1.7 Loss Functions

L_total = λ_ω · L_ω + λ_div · L_div + λ_bnd · L_bnd + λ_pos · L_pos + λ_aniso · L_aniso + λ_vol · L_vol
LossFormulaPurpose
L_ωmean(|ω_current - ω_target|)Preserve vortex structures
L_divmean((∇·u)²)Enforce incompressibility
L_bndmean(|u·n|²) at wallsNo-penetration condition
L_posmean(|μ - μ_advected|²)Prevent particle drift
L_anisomean(max(ratio, 1.5) - 1.5)Limit elongation
L_volmean((det(S) - det(S_ref))²)Regularize Gaussian size

1.8 Gradient Projection

When vorticity and divergence gradients conflict (negative dot product), project the divergence gradient orthogonally:

g'_div = g_div - (g_div · g_ω / g_ω · g_ω) · g_ω

1.9 Covector Advection

After RK4 advection, the inverse covariance updates via the flow Jacobian F = ∂Φ/∂x:

Σ^{-1}_new = F^T · Σ^{-1}_old · F

1.10 Divergence-Free Stream Function (2D Only)

An exactly divergence-free velocity field from a scalar stream function φ:

φ(x) = Σ_i φ_i · G_i(x)
u(x) = J · ∇φ(x)    where J = [[0, -1], [1, 0]]

This gives u_x = -∂φ/∂y and u_y = ∂φ/∂x, which is automatically divergence-free.

2.3 GPGPU Strategy

All "computation" in WebGL 2 happens by:

  1. Binding input data as float textures (RGBA32F)
  2. Rendering a fullscreen triangle (covers the viewport)
  3. A fragment shader reads inputs via texelFetch(), computes, writes to gl_FragColor
  4. Output goes to a Framebuffer Object (FBO) with float texture attachment
  5. Ping-pong between two FBOs for iterative algorithms
  6. MRT to write up to 4 vec4 outputs per pass

2.4 Data Layout in Textures

For N Gaussians, use a texture of width W = ceil(sqrt(N)), height H = W. Each Gaussian's index i maps to texel (i % W, i / W).

2D Gaussian data (2 textures):

Solver Loop (Per Frame)

  1. GPU Reseed Pass — check anisotropy, mark splits
  2. GPU Advection Pass — RK4 move particles, covector advect weights
  3. GPU Compute ω_target — evaluate vorticity at sample points
  4. GPU Projection Loop (K iterations):
    1. Evaluate current ω and ∇·u at sample points
    2. Compute loss gradients w.r.t. weights and scales
    3. Apply gradient descent update (Adam-like)
    4. Apply gradient projection if ω/div gradients conflict
  5. CPU Build spatial grid — bin particles for fast neighbor lookup
  6. GPU Visualization Pass — evaluate field, color-map, composite

Phase 2 — Gaussian Spatial Representation

Implement the core data structure: Gaussians encoded in textures with analytical derivative support.

Step 2.1: Gaussian Parameter Initialization CPU

Create js/simulation/gaussians.js:

  • class GaussianField — N particles, texSize = ceil(sqrt(N))
  • CPU arrays: positions[N*2], logScales[N*2], rotations[N], weights[N*2]
  • initGrid(domainMin, domainMax, nx, ny) — regular grid placement, initial scales ~1.5× spacing
  • uploadToGPU() / readbackFromGPU() — pack/unpack from textures

Step 2.2: Gaussian Evaluation Functions GLSL

Create shaders/common/gaussian_eval.glsl — shared #include-style functions:

mat2 getInvCovariance(float theta, vec2 logScale) {
    vec2 s_inv = 1.0 / exp(logScale);
    float c = cos(theta), sn = sin(theta);
    mat2 R = mat2(c, sn, -sn, c);
    mat2 RS = R * mat2(s_inv.x, 0, 0, s_inv.y);
    return transpose(RS) * RS;
}

float evalGaussian(vec2 x, vec2 mu, mat2 sigmaInv) {
    vec2 d = x - mu;
    return exp(-0.5 * dot(d, sigmaInv * d));
}

vec2 gradGaussian(vec2 x, vec2 mu, mat2 sigmaInv, float g) {
    return -(sigmaInv * (x - mu)) * g;
}

Step 2.3: Velocity Evaluation Shader GLSL

Create shaders/simulation/eval_velocity.frag — for each screen pixel, sum all Gaussian contributions: u(x) = Σ_i w_i · G_i(x)

Step 2.4: Velocity Gradient Tensor Shader GLSL

Create shaders/simulation/eval_velocity_grad.frag — output via MRT:

  • location 0: vec4(u_x, u_y, 0, 0) — velocity
  • location 1: vec4(∂ux/∂x, ∂ux/∂y, ∂uy/∂x, ∂uy/∂y) — gradient tensor

Vorticity = grad.z - grad.y, Divergence = grad.x + grad.w

Step 2.5: Verification

  • Initialize Taylor-Green vortex: u = (sin(x)cos(y), -cos(x)sin(y))
  • Fit Gaussian weights, render velocity magnitude — checkerboard pattern
  • Compare vorticity ω = -2sin(x)sin(y) with computed — visual match

Phase 3 — Velocity Field Evaluation

Build the spatial acceleration structure and efficient field evaluation pass.

Step 3.1: Spatial Grid Construction CPU

Create js/simulation/spatial-grid.js:

  • Divide domain into 32×32 cells
  • Each Gaussian has effective radius ~3·max(scale)
  • CPU-side: read positions, bin into cells, upload index texture
  • Format: 2D texture, row = cell, columns = Gaussian indices, max 32 per cell

Step 3.2: Grid-Accelerated Evaluation GLSL

Create shaders/simulation/eval_velocity_grid.frag — look up 3×3 neighboring cells, only evaluate indexed Gaussians.

Step 3.3: Vorticity & Divergence Field GLSL

Create shaders/simulation/eval_vorticity_div.frag — analytical vorticity and divergence using Gaussian gradient formulas. Output: vec4(ω, div, 0, 0).

Step 3.4: Verification

  • Taylor-Green vorticity field — smooth sine pattern
  • Divergence near zero everywhere
  • Brute-force vs grid-accelerated — identical within float precision

Phase 4 — Advection (RK4)

Move Gaussian particles through the velocity field using 4th-order Runge-Kutta integration.

Step 4.1: Particle Advection Pass GLSL

Create shaders/simulation/advect_particles.frag:

// Each fragment = one Gaussian particle
// RK4 integration:
k1 = dt * evalVelocity(pos)
k2 = dt * evalVelocity(pos + 0.5*k1)
k3 = dt * evalVelocity(pos + 0.5*k2)
k4 = dt * evalVelocity(pos + k3)
newPos = pos + (k1 + 2*k2 + 2*k3 + k4) / 6

Step 4.2: Flow Jacobian Computation GLSL

Compute velocity gradient ∂u/∂x at particle position. First-order Jacobian: F = I + dt · ∇u. For higher accuracy, accumulate through RK4 stages.

Step 4.3: Covector Advection Pass GLSL

Create shaders/simulation/advect_covector.frag:

  1. Compute flow Jacobian F
  2. Update inverse covariance: Σ^{-1}_new = F^T · Σ^{-1}_old · F
  3. Decompose back to (θ_new, logS_new) via 2×2 SVD
  4. Covector-advect weight: w_new = F^{-T} · w_old

Output via MRT: updated posScale + rotWeight textures.

Step 4.4: Domain Boundary Clamping

After advection, mark out-of-domain particles inactive (zero weight) or reflect back.

Step 4.5: Verification

  • Single Gaussian in uniform flow u = (1,0) — translates right
  • Taylor-Green: particles follow streamlines
  • Covector advection in shear flow: rotation updates correctly
  • Energy roughly conserved over many steps

Phase 5 — Projection & Optimization

The most critical phase. Enforce physical constraints by optimizing Gaussian weights and scales. All gradients are analytical — no autograd needed.

Step 5.1: Target Vorticity Computation GPU

Create shaders/simulation/compute_target_vorticity.frag — evaluate vorticity of the advected field at a regular grid of sample points (128×128). This is the target that projection must preserve.

Step 5.2: Loss Gradient Computation (Analytical) GLSL

Create shaders/simulation/compute_loss_gradients.frag — the core shader. Each fragment = one Gaussian. Inner loop sums contributions from sample points:

// Vorticity loss gradient w.r.t. weight:
∂L_ω/∂w_{i,x} = (1/M) Σ_j sign(ω(x_j) - ω_target(x_j))
                    · (-[Σ^{-1}(x_j-μ_i)]_y) · G_i(x_j)

// Divergence loss gradient w.r.t. weight:
∂L_div/∂w_{i,x} = (2/M) Σ_j div(x_j)
                     · (-[Σ^{-1}(x_j-μ_i)]_x) · G_i(x_j)

Also compute scale gradients analogously.

Step 5.3: Gradient Projection GLSL

Create shaders/simulation/gradient_project.frag:

float d = dot(grad_div, grad_omega);
if (d < 0.0) {
    grad_div -= (d / dot(grad_omega, grad_omega)) * grad_omega;
}
combined = lambda_omega * grad_omega + lambda_div * grad_div;

Step 5.4: Adam Optimizer Step GLSL

Create shaders/simulation/adam_update.frag — per-Gaussian Adam in a fragment shader. Maintains first/second moment textures (t_adam_m, t_adam_v). Typical: lr=0.01, β1=0.9, β2=0.999.

Step 5.5: Projection Iteration Loop CPU

JavaScript orchestrates K iterations per time step:

for (let k = 0; k < K; k++) {
    evalVorticityDivPass.execute(t_currentVorDiv);
    computeGradientsPass.execute(t_gradWeights, t_gradScales);
    gradientProjectPass.execute(t_projectedGrads);
    addRegularizationPass.execute(t_totalGrads);
    adamUpdatePass.execute(t_rotWeight_out);
    adamUpdateScalePass.execute(t_posScale_out);
    pingPong.swap();
}

Step 5.6: Boundary & Regularization Losses GLSL

Create shaders/simulation/boundary_loss.frag — sample walls, penalize u·n. Add anisotropy + volume regularization gradients.

Step 5.7: Verification

  • Taylor-Green: divergence decreases after projection
  • Vorticity error stays small through advect+project
  • Gradient projection eliminates ripple artifacts
  • Adam converges in <16 iterations
  • Stable for >500 time steps

Phase 6 — Adaptive Reseeding

Split elongated Gaussians to maintain representation quality.

Step 6.1: Anisotropy Detection GPU

Create shaders/simulation/detect_splits.frag — compute max(s)/min(s) per Gaussian, flag those ≥ threshold (1.5–2.0).

Step 6.2: Splitting CPU

Read back flags. For each flagged Gaussian, create 2 children along the major axis:

  • Positions offset by ±0.5·R·[s_major, 0]
  • Major scale halved, minor scale unchanged
  • Weights halved
  • Resize textures, re-upload, rebuild spatial grid

Step 6.3: Post-Split Refinement

Run 4–8 projection iterations to correct the field representation after splitting.

Phase 7 — Visualization & Rendering

Render the fluid field with informative and beautiful colormaps.

Step 7.1: Vorticity Colormap GLSL

Create shaders/rendering/render_vorticity.frag — diverging blue-white-red colormap. Negative ω → blue (clockwise), positive ω → red (counter-clockwise).

Step 7.2: Velocity Magnitude Colormap GLSL

Create shaders/rendering/render_velocity.frag — sequential viridis-like colormap of |u|.

Step 7.3: Dye Advection (Passive Tracer) GLSL

Create shaders/rendering/advect_dye.frag — semi-Lagrangian backward trace through velocity field. Bilinear sample dye texture at traced-back position. Users inject colored dye via mouse.

Step 7.4: Gaussian Debug Visualization GLSL

Create shaders/rendering/render_gaussians.vert + .frag — instanced rendering of oriented ellipses. Color by weight direction. Useful for debugging.

Step 7.5: Screen Composite GLSL

Create shaders/rendering/composite.frag — layer vorticity/velocity background + dye overlay + debug ellipses + UI.

Step 7.6: Verification

  • Taylor-Green vortex: 4 counter-rotating cells visible
  • Dye shows smooth swirling patterns
  • Gaussian ellipses align with local flow
  • 60fps at 256×256

Phase 8 — 3D Extension

Extend the solver to three dimensions with volume rendering.

Step 8.1: 3D Gaussian Parameters

Extend to 4 textures: position, logScale (3 components), quaternion rotation, weight (3 components). Total 13 floats per Gaussian.

Step 8.2: 3D Evaluation Shader GLSL

mat3 getInvCovariance3D(vec4 quat, vec3 logScale) — build rotation from quaternion, compute Σ^{-1}.

Step 8.3: Quaternion Utilities GLSL

Create shaders/common/quaternion.glsl — quatToMat3, mat3ToQuat, quatMul, quatNormalize.

Step 8.4: 3D Velocity in 3D Texture

Evaluate field on 64×64×64 grid. Render to 2D atlas (64 slices), copy to sampler3D via gl.texSubImage3D().

Step 8.5: 3D Vorticity (Vector)

ω = ∇ × u requires full 3×3 gradient tensor. Pack into atlas textures.

Step 8.6: 3D RK4 + Covector Advection

Same structure as 2D with vec3/mat3. Polar decomposition of 3×3 for quaternion extraction.

Step 8.7: Volume Rendering GLSL

Create shaders/rendering/volume_raycast.frag:

  1. For each pixel, compute ray from camera
  2. March through domain with fixed step
  3. Sample vorticity magnitude from 3D texture
  4. Apply transfer function (magnitude → color + opacity)
  5. Front-to-back alpha compositing
  6. Early ray termination at α > 0.99

Step 8.8: 3D Projection

Same loss structure as 2D. Vorticity is a 3-vector. Optionally add helicity conservation (h = ω · u). Sample grid: 32³ = 32K points.

Step 8.9: Verification

  • Leapfrog vortex rings — two coaxial rings pass through each other
  • Volume render shows ring structures
  • Divergence near zero after projection
